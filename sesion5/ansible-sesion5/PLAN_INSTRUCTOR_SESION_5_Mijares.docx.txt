4. Guión para Mijares - Qué decir en cada LAB

LAB 5.1 Guión:
"Chicos, ¿recuerdan LAB 3.1 donde teníamos 30 líneas en un playbook para configurar httpd? Eso no escala. Ahora lo convertimos en role. Fíjense que en defaults ponemos app_port 8080, que es sobreescribible, y en vars ponemos la lista de directorios que es fija del role. En tasks, todo lo que hicimos en Sesión 3 pero ahora dentro del role. Importante: como estamos sin internet, no podemos usar validate httpd -t porque no hay binario, usamos grep -q Listen, que valida offline. Handlers igual que Sesión 3 con listen."

Comando clave para mostrar en pantalla:
ansible-galaxy role init roles/telcel_app --offline
cat roles/telcel_app/tasks/main.yml
ansible-playbook playbooks/test-telcel-app.yml --diff --limit servera

LAB 5.2 Guión:
"Mismo patrón para logrotate. En Sesión 3 teníamos postrotate con systemctl reload rsyslog, pero aquí no hay systemd, así que solo hacemos echo a /tmp. La idea es que entiendan el concepto de handler, no que rotemos logs reales. Validate con grep daily."

LAB 5.3 Guión:
"Ahora lo crítico para TELCEL: secrets. ¿Quién quiere subir su password de DB a Git en claro? Nadie. Para eso Vault. Creamos ~/.vault_pass c

on chmod 600, nunca 777. Luego ansible-vault create. Fíjense que el archivo queda cifrado, con $ANSIBLE_VAULT. En el playbook referenciamos db_password: {{ vault_db_password }}. Y en la task que crea secrets.conf usamos mode 0600 y no_log true para que no salga en logs. Si alguien intenta correr sin --vault-password-file, falla, que es lo que queremos."

Demo impactante:
cat inventory/group_vars/web/vault.yml -> se ve cifrado
ansible-vault view ... -> se ve en claro
ansible-playbook site.yml --diff -> falla sin pass
ansible-playbook site.yml --vault-password-file ~/.vault_pass --diff -> OK

LAB 5.4 Guión:
"Finalmente site.yml, que es el orquestador. Ya no tenemos 5 playbooks sueltos, tenemos 1 site.yml que llama roles. Esto es lo que se corre en prod. Y lo más importante: si lo corro 2 veces seguidas, la segunda debe dar 0 changed, eso es idempotencia. Si da changed, algo está mal en su role."

Mostrar:
ansible-playbook site.yml --vault-password-file ~/.vault_pass --diff  # 1ra changed
ansible-playbook site.yml --vault-password-file ~/.vault_pass --diff  # 2da 0 changed -> aplauso

6. Troubleshooting - Qué hacer si falla (Mijares)

Problema: dnf install httpd falla DNS no internet
Solución: Esperado, es offline. No usar dnf. Usar file/copy/template. Decir: "Este lab es offline a propósito, en TELCEL prod a veces no hay internet en segment de O&M"

P

roblema: validate httpd -t falla no such file
Solución: Cambiar a validate: sh -c "grep -q 'Listen' %s && cat %s"

Problema: service: name=httpd state=restarted falla systemd
Solución: No usar service/systemd. Usar command: cat + debug con listen

Problema: ansible-vault pide password interactivo y se atora
Solución: Usar --vault-password-file ~/.vault_pass siempre. Verificar chmod 600

Problema: Segunda corrida da changed, no idempotente
Causa: template con variable que cambia cada vez (ansible_date_time). Quitar esa variable o usar changed_when:false en task de validación
Solución: En templates no usar ansible_date_time.iso8601 si no es necesario

Problema: Alumno no ve vault porque no tiene ~/.vault_pass
Solución: Mijares crea uno y lo comparte, o usar --ask-vault-pass y que escriban TelcelVault2025

Problema: Roles no encontrados
Solución: Verificar ansible.cfg roles_path = ./roles y que estén en ~/taller-ansible-telcel/roles/
